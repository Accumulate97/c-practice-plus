## 三、根因：A「代码挤在一起」= `code_starter` 单行挤压（数据问题）

### 3.1 什么字段被挤压

| 字段 | 总数 | 无换行 | 含 >100 字符行 |
|---|---|---|---|
| `code` | 552 | **0** | 1 |
| `reference` | 479 | 0 | 93 |
| **`code_starter`** | 441 | **110** | 94 |
| `solution` | 139 | 0 | 0 |
| `fixed_code` | 103 | 0 | 0 |
| `stdin` | 26 | 25 | 0 |

- `code`、`solution`、`fixed_code`、`reference` 均**无换行缺失**——这些字段是正常的多行代码。
- **只有 `code_starter` 存在 110 道整体单行**。
- `stdin` 的 25 个无换行是 `"5 8"` / `"ab"` 等**简单输入**，非缺陷。

### 3.2 按题型归因

无换行 `code_starter`：**仅 `algorithm_impl` = 110 道**（其 326 道有 code_starter 中占 110；`api_drill` 40 / `stdlib_reimpl` 35 / `timed_impl` 40 全部多行正常）。

### 3.3 典型样例（取自 `c-ch05.json`）

```
c-ch05-alg-101 code_starter = "int main(){int n;scanf(\"%d\",&n);int s=0;/*__BLANK__*/printf(\"%d\",s);}"
c-ch05-alg-203 code_starter = "int main(){int n;scanf(\"%d\",&n);int s=0;for(int i=1;i<=n;i++){/*__BLANK__*/}printf(\"%d\",s);}"
c-ch05-alg-201 code_starter = "int main(){int n;scanf(\"%d\",&n);int p=1;if(n<2){printf(\"0\");return 0;}for(int i=2;i*i<=n;i++){/*__BLANK__*/}printf(\"%d\",p);}"
```

特征：全在一行、无缩进、`int main(){` 无空格、多语句同行、`scanf`/`printf` 与语句之间无空格、`/*__BLANK__*/` 占位符。

### 3.4 为什么是「数据问题」而非「渲染问题」

- `CodeBlock.tsx` 用 `<pre>`（默认 `white-space: pre`，保留换行），`CodeEditor.tsx` 用 `<textarea wrap="off">`（天然保留换行）。
- 两组件均无 CSS 折叠换行。渲染侧正确。
- 因此**只改前端无法解决**——因为 `code_starter` 是**数据源**，前端原样展示。需要在阶段 2 把 110 道 `algorithm_impl` 的 `code_starter` 重排为多行 + 缩进 + 运算符两侧空格。
- **红线提醒**：格式化时**不得改变语义**（不碰 `/*__BLANK__*/` 占位符与判分逻辑），且必须**同步**修改对应的 `reference` / `solution` 保持一致（若学生对 content 比对）。

## 四、缺陷 B：160 道 `code_starter` 缺 `#include <stdio.h>`

### 4.1 结论

用 `scanf` / `printf` / `puts` 等标准库 IO 函数、但 `code_starter` 中无任何 `#include <stdio.h>` 的题：
- **160 道**（全部 `algorithm_impl`），其中**110 道同时是单行挤压**（即 A 问题），另有 **50 道是多行但缺 include**。
- 样例（多行缺 include）：`c-ch06-alg-161`、`c-ch06-alg-162`
  - `c-ch06-alg-161` code_starter 以 `int main(){ int n,k; scanf(...); ... }` 直接开始，**无 `#include <stdio.h>`**。
  - `c-ch06-alg-162` 同。

### 4.2 为什么是缺陷

- `ProgrammingRenderer.initialCode` 直接用 `problem.code_starter`（或空则 SCAFFOLD），学生在该正文上修改后，`code` **原样**提交给 `runStdinTests` / `JudgeClient.runTests`。
- `RunRequest.code` 直接进 Godbolt 编译，**无任何预置 include 包裹**。
- `-std=c99` 下调用无声明函数（`printf`/`scanf`）属**隐式声明**：C99 是 constraint violation，多数编译器报 **error**（至少 `-Werror=implicit-function-declaration` 下必错）。即使只报 warning，也是不该出现的起点代码。
- 学生从这样的 code_starter 开始，若只补 TODO 而不加 include，**提交后无法编译** → 被判 `compile-error`，体验极差。

### 4.3 影响面

- 这 160 道题大多数在 `c-ch05`、`c-ch06`（循环/数组/指针的 `algorithm_impl` 批量），是**主力——编程题**的起点代码。
- 应在阶段 2 统一为这 160 道的 `code_starter` **补上 `#include <stdio.h>`**（并顺带处理单行挤压），且与其 `reference` 保持一致。

## 五、E「expected:""」判定为**非缺陷**（边界空输出）

初版扫描把 65 道含 `expected:""` 的题标记为疑似「答案不可验证」。**经核实，这是正常边界用例，不是缺陷**：

- 判分归一化（`src/judge/backends/base.ts:24-29`）：`normalizeOutput` = 换行统一 → 逐行去行尾空白 → **剥离整体末尾换行与空白**。
- 因此程序**输出仅一个 `\n`** 或**什么都不输出**时，归一化后为 `""`，与 `expected:""` 正确匹配。
- 实例：
  - `c-ch06-alg-103`：`{"stdin":"0","expected":""}` —— n=0，数组为空，逆序打印无元素，末尾 `printf("\n")` 被归一化为空。✓
  - `c-ch05-alg-202`：`{"stdin":"1","expected":""}` —— n=1，素数循环不执行，无任何输出。✓
  - `c-ch05-cc-820`：`{"stdin":"2","expected":""}` —— 小于 2 无素数，`printf("\n")` 归一化为空。✓

**结论**：这 65 道是**测试设计严谨的体现**（覆盖 0/1 等空输出边界），不是数据缺陷，**无需修复**。

## 六、F「表述不严谨」抽样发现（29 道人工评审）

按 `docs/specs/04-question-types.md` 的严谨性要求，抽样发现以下类别的问题：

### 6.1 IO 输入格式部分未说明（中）
- 部分 `algorithm_impl` / `code_completion` 的 `testCases` 用 `scanf("%d%d")` 接收 `"4 5"` 与 `"4 5"`（空格分隔），但题干只说「输入两个正整数 m、n」，**未明说空格/换行分隔**，也未给出 `input_format`。学生理论上可构造任意分隔（制表符/多空格），`scanf` 均能解析，故不影响判分，但严谨性欠佳。建议在 `input_format` 或题干中注明「空格分隔」。
- `c-ch06-alg-146`（统计出现次数）`testCases` 用 `"5 3\n1 2 3 4 5"`——同行 `n x` 再接一行数组；题干未写明「第一行 n 和 x，第二行 n 个数」。属 IO 格式未说明。

### 6.2 边界/约束缺失（中）
- 多数题只说「输入一个正整数 n」，但 `testCases` 覆盖 `n=0`、`n=1` 等边界，甚至 `n=0` 的用例期望空输出。题干未声明「n 可能为 0」。建议在 `input_format` 或题干补「0 ≤ n ≤ …」约束。
- `c-ch05-alg-202` 的 `reference` 用 `int` 累加素数，若 n 很大可能溢出（但测试用例 n≤30，实际不触发）。属「约束未显式声明」范畴。

### 6.3 术语/概念表述（中）
- `c-ch09-alg-153` 题干出现「双重指针」——但在 C 语境下更准确是「两个指针变量 p、q 嵌套遍历」（不是「双重指针/二级指针 `int **`」）。术语易与学生已有知识混淆。应改为「两个指针」。
- `c-ch09-mdb-111`（动态数组求和）：`code` 用 `p = malloc(...)` 未判空、`for(i=0;i<=n;i++)` 越界、未 `free`。但 `fixed_code` 把 `malloc` 加了 `(int *)` 强转——这是 **C++ 风格**，纯 C 中 `malloc` 返回 `void*` 可隐式转换，**无需强转**；且本项目禁止 C++ 语法。应去掉强转（`p = malloc(n * sizeof(int))`）。

### 6.4 注释与要求不一致（低）
- `c-ch05-alg-308` code_starter 注释 `// TODO: 判定是否在边框上 i==1||i==m||j==1||j==n` 把**答案提示**写进了注释，削弱「填空/编写」的考查力度。应改为中性提示（如 `// TODO: 判断当前格是否在边框上`）。

### 6.5 TODO/FIXME 注释（修订：内容已中文，仅关键字为英文）
- 复查结论（`tmp/scan-todo.mjs`）：全部 217 处 `TODO`/`FIXME` 注释**内容已是中文**（byLang cjk=217, ascii=0），仅使用英文 `TODO:` 关键字（`algorithm_impl` 140、`api_drill` 42、`stdlib_reimpl` 35）。
- 初版报告此节的「213 道英文 TODO」是**误判**——实为「内容中文、关键字英文」。`TODO:` 是通行习惯，改写反而降可读性。**决定：不改**，仅更正本报告表述。

### 6.6 其他（低）
- `c-ch05-mdb-001` 的 `code`/`fixed_code` 首行缩进异常（`      int main(void) {` 前缀 6 空格），格式不齐。
- `reference` 字段 93 道含 >100 字符长行（多为 `c-ch06` 数组/二分等，属合法长语句），仅个别需要换行。
